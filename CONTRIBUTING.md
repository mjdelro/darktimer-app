# Contributing

Code, documentation, and recipe-data contributions are accepted under
Apache-2.0. By submitting a contribution, you represent that you have the right
to provide it under those terms.

## Recipe contributions

darkTimer accepts two clearly labeled kinds of recipe data:

- `manufacturer-published`: minimum factual values manually transcribed from a
  named manufacturer technical publication.
- `community-reported`: an original empirical darkroom result contributed with
  permission and at least one successful test.

Use the in-app submission form to create a public GitHub issue. Discord and
other private messages may be used to collect the details and permission, but
do not paste private messages, screenshots, email addresses, or private message
URLs into the issue. Use the contributor's chosen public credit, including
`Anonymous` when requested.

Every recipe submission must include the film, format, EI, developer, dilution,
time, temperature, agitation method, source or test date, and any process limits
needed to interpret the result. Community reports must also state the number of
successful tests.

The submitter must affirm all of the following:

1. The recipe comes from their own testing or the named manufacturer
   publication, not from a third-party database, table, or copied user notes.
2. If another person's test is being submitted, that person gave written
   permission to publish it and use the chosen attribution.
3. The factual values and any original notes are intentionally submitted for
   inclusion in darkTimer under Apache-2.0.

Do not scrape or copy a third-party database, prose passage, table, layout,
user notes, or compilation without a written license that allows repository
redistribution. A maintainer must review provenance, assign the final source ID
and issue URL, and add or update catalog tests before merging a recipe.

For commits and pull requests, use a signed-off commit to certify that you
created the contribution or have the right to submit it under these terms:

`Signed-off-by: Your Name <your.email@example.com>`

The project may reject data whose provenance or redistribution basis is unclear.
